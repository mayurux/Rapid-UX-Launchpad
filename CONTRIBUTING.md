# Contributing to Rapid UX Launchpad

Thanks for helping improve Rapid UX Launchpad. Contributions can include clearer instructions, stronger workflow safeguards, realistic examples, typo fixes, and feedback from using the skills.

## Before opening a change

1. Check existing issues and pull requests to avoid duplicating work.
2. For substantial changes, open an issue first to discuss the problem and proposed approach.
3. Keep changes focused. One pull request should solve one clear problem.

## Contribution principles

- Preserve the five-stage workflow unless a change is intentionally proposed and explained.
- Keep human approval checkpoints explicit.
- Do not weaken evidence discipline or allow fabricated research, metrics, product facts, or capabilities.
- Preserve the named handover contracts between skills.
- Keep each skill self-contained enough to be usable, while avoiding unnecessary duplication.
- Use inclusive, plain language and concise instructions.
- Label examples and sample data as illustrative.

## Pull request checklist

- [ ] I have explained the problem and why the change is needed.
- [ ] I have checked that the change does not contradict another skill.
- [ ] I have preserved approval gates and handover requirements, or explained any intentional change.
- [ ] I have checked links, filenames, and Markdown formatting.
- [ ] I have not included confidential information or unverified claims.

## Reporting issues

Use the GitHub issue templates for bugs and feature requests. Include the skill number, the expected behaviour, what happened, and a small reproducible example where possible.

By contributing, you agree that your contribution may be distributed under the repository's license. If no license is present, please discuss licensing with the maintainer before submitting substantial content.
